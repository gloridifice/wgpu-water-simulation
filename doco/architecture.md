# Current architecture

This document records boundaries implemented in the current code. Unimplemented proposals are kept in change directories and are not current functionality.

## Program entry points

- Rust 2024 workspace; the root package `water-simulation` enables the `ocean` feature by default. The root package is the only default member, and `cargo run` starts GPU Ocean.
- `src/bin/ocean.rs` provides the GPU Ocean entry point and verification and preview options.
- `src/bin/slider_lab.rs` and `src/ocean/labs/slider_lab/` provide a standalone rectangular slider appearance window. It shares `yummy_egui::ParameterSlider` with the production panels and reuses the library's default theme and parameter grid; experimental adjustments affect only this window, run no simulation, and do not read or write configurations. See [Slider appearance lab](guides/slider-lab.md) for startup and interaction.
- `src/bin/ocean_profile.rs` profiles the offscreen production path with read-only configuration: it advances in fixed 1/60 simulation-second steps and, after warmup, records separate GPU timestamps for FFT, offshore foam, full SWE (including spray sources and copying), particles, and drawing. It reads back state/images at the end for A/B comparison and excludes UI and presentation. When in-pass timestamps are supported, `render/timing.rs` breaks down drawing stages without splitting the render pass; initialization frame and post-warmup statistics are separate, and queries are batched according to device limits. `--optics-ab` alternates four caustics/refraction combinations on the same simulation state for paired measurements without advancing physics; `--optics-methods` compares all off, physical caustics with fast refraction, physical caustics with physical refraction, and the original configuration. See [Foam diagnostics and benchmarks](guides/foam-lab.md#production-path-offscreen-profiling) for instructions.
- `src/bin/foam_lab.rs` provides standalone offline foam transport comparisons: the default diagnostic entry point calls production foam flux, source terms, and texture motion and outputs density snapshots and errors under a fixed analytical flow; `--benchmark` in `foam_lab/benchmark.rs` calls the production SWE pipeline, warms up and repeatedly times fixed sparse/dense/model terrain/obstacle and model dual-concentration plus nonzero incident-wave inputs, and exports single-step state. Neither reads or writes personal configuration; see [Foam diagnostics and benchmarks](guides/foam-lab.md).
- `crates/tui-2d-prototype/` is a standalone CPU package: `src/main.rs` selects 2D PIC/1D shallow water and TUI/batch operation, `src/pic/` and `src/solver.rs` provide terminal-independent solvers, and `src/tui/` and `src/shallow_tui/` handle interaction. Tests and the `pic_probe` example belong to this package. Its Cargo package name is `tui-2d-prototype`, its library name is `tui_2d_prototype`, and its binary remains named `water-simulation`; start it from the root with `cargo run -p tui-2d-prototype`.
- `crates/common/` is a standalone common framework library, used by the root package only under the `ocean` feature; it depends on neither the root package nor simulation business logic. The root package does not depend on the CPU package, Ratatui, or Crossterm. The root package, common library, and CPU package share the root `Cargo.lock` and build directory, and `cargo test --workspace` covers all three; the `yummy_egui` component library comes from crates.io and is not a workspace member. `crates/tall-cell-fluid/` remains an independent workspace and is not included here.

## Common desktop framework

`crates/common/` provides the following mechanisms used by Ocean; it does not own ocean parameters, panel registries, or simulation advancement rules:

- `app.rs`: `WindowScene` and the single-window event loop, window creation, limited presentation frame counts, skipping frames while minimized, and Surface recovery. Optional `WindowScene::poll_commands` executes control commands in an event-loop phase outside rendering and remains responsive when the window cannot present. The application sends business events to egui before deciding shortcuts; it controls computation and drawing order. Optional raw device events pass through `WindowScene::device_event` to applications capturing the mouse; the default empty implementation does not change Ocean's viewport dragging policy.
- `gpu/`: a shared wgpu device and queue, explicit readback, and nonblocking timestamp sampling. The original `gpu/timer.rs` adapts Ocean solver order, substeps, and simulation-time metadata; the common timer reports only actual GPU milliseconds.
- `ui/`: egui-winit/wgpu integration and a native-texture viewport, retaining the existing sRGB/egui color conventions. Applications install fonts; controls and themes continue to use crates.io yummy_egui.
- `ui/layout.rs`: canonical layouts parameterized by application panel type, validation, Dock conversion, and restoration of temporarily hidden positions. Ocean registers six workspaces, names, default layouts, parameter dependencies, and v1/v2→v3 migration; an old layout missing a new workspace uses its default layout.
- `settings/`: generic working state, read-only default snapshots, named configurations, manual saving, corrupt-file backups, and atomic replacement in the same directory. `sidecar.rs` independently handles throttled layout saving, errors, and explicit repair permission. Applications supply serialization types, validation, filenames, and version policy; Ocean retains its original top-level JSON, configuration paths, and save semantics.
- `camera.rs`: orbit camera pose, perspective matrices, and horizontal panning independent of ocean parameters. Ocean's original camera configuration and CameraUniform remain in their original module without changing fields or GPU binary layout.
- Optional `control.rs`: an rmcp stdio service forwards parameter queries and batch updates, actions, fixed stepping, and screenshots to a bounded scene-command queue exclusively owned by the application. It holds no application configuration or business buttons. Ocean's headless and scene-only windows use it; the original Dock desktop window does not.

The common library extracts desktop mechanisms only; it does not provide a unified solver, complete scene renderer, or character physics. Standalone lab windows retain their own application adapters. See the [common framework guide](guides/common.md) for framework boundaries, Ocean regression evidence, and verification commands.

## GPU Ocean

`src/ocean/` is organized by responsibility into `app/` (windows and snapshots), `gpu/` (device and timing), `parameters/` (parameter defaults and validation), `simulation/` (offshore, nearshore, spray), `scene/` (models, terrain, colliders), `render/` (scene drawing, optics, textures), `ui/` (panels and layouts), `settings/` (session and named library), and `labs/` (experiments). `camera.rs` retains ocean camera configuration and CameraUniform, delegates geometry to common, and does not depend on a window. The parameter layer does not depend on application, UI, or GPU resources. `gpu/context.rs` compatibly re-exports common's device implementation without referencing simulation or rendering.

`ocean/mod.rs` retains the original `shore`, `foam`, `spectrum`, `spray`, `model`, `terrain`, `collider`, `optics`, `skylight`, `viewer`, and `foam_weight_lab` public paths; `gpu/mod.rs` retains re-exports of Gpu, Ocean, Renderer, CameraUniform, and Error. Compatibility entry points do not hold a second implementation; internals use the actual responsibility paths. The original sky depth chart entry point remains exported by the compatibility facade, while the chart implementation belongs to `ui/panels/optics.rs` and sky calculations do not depend on the GUI. Rust shorthand paths below are relative to `src/ocean/`.

- WGSL files belong to their module's `shaders/` subdirectory: shared FFT in `simulation/spectral/`, offshore foam in `simulation/offshore/`, shared SWE definitions/computation/reading in `simulation/nearshore/`, spray in `simulation/spray/`, drawing and optics in `render/`, color mips in `render/textures/`, and the foam weight lab in `labs/foam_weight_lab/`. Offline transport diagnostics retain `src/bin/foam_lab/shaders/`; the standalone liquid library uses `src/gpu/shaders/` and `src/demo/shaders/` respectively. Rust embeds these at compile time relative to source files with `include_str!` / `include_bytes!`; cross-module references use the single original, preserving bytes and concatenation order without relying on the working directory or external shader files.
- `parameters/lake.rs`, `scene/lake.rs`, and `simulation/animated_lake/` provide procedural lake animation independent of SWE, optionally layered with shared FFT height. A periodic radial-noise shoreline, bowl-shaped bed, and rocks form one single-layer height field; a CPU separable Euclidean distance transform produces an SDF with exposed rock holes. Depth/SDF normalized coordinates share a lake-centered angular envelope. A CPU f64 clock manages a fixed 128-slot event pool and one scheduled reflection; the GPU reads 80-byte wave records and calculates final height and slope separately, with no normal-frame state readback. Reflections inherit sectors, reverse propagation progress, and attenuate; diffraction, conservation, and physical specular reflection are not provided.
- `render/lake.rs` handles opaque lakebed/rock predrawing and scene composition; the water uses Renderer’s separate lake vertex pipeline. `render/shaders/lake_{sample,water,ground}.wgsl` reads the same static terrain and animated wave field. The ocean water layout adds a separate group 1 to publish the field, without changing the SWE simulation ABI. The lake advances shared FFT as needed but does not advance SWE/foam/spray simulation. Its water adapter combines metric SDF and procedural cellular net patterns into a separate cartoon shoreline foam overlay, with parameters edited live in the Lake Terrain panel. A separate foam-coordinate compute integrates backward along a centripetal field with a nearshore velocity gradient, publishing two sets of metric material displacements offset by half a period; water interpolates only wet-domain coordinates and smoothly crossfades them, while a positive dot product of flow and SDF gradient restricts display on the backflow side. Animation follows the absolute lake clock and maintains no transported density. Final height first adds FFT (by default faded by still-water depth and shore distance, with fading switchable live), then constrains troughs and differences the result to produce slopes. Ocean and lake share medium integration, fast/supported physical refraction paths, Fresnel, SSR, sun highlights, and optical diagnostics through `render/water/shaders/material.wgsl`; geometry/masks/foam are scene-adapted, and HDR remains shared. Physical caustics and physical refraction are explicitly unavailable in lake mode and do not read the old ocean wave surface. Windows and snapshots call the same event/wave-field entry point; lake snapshots advance events from zero to the target time without truncated warmup. Parameters are in `OpticsConfig::lake`, disabled by default and compatible with old sessions; playback history is not persisted. The dedicated real-GPU entry point is `--verify-lake`, and full `--verify` also includes the lake. See the [lake animation specification](specs/animated-lake.md).
- `simulation/spectral/{mod,spectrum}.rs` provides shared `FftWaves`: spectrum initialization, GPU evolution, inverse FFT, and six-channel output. `shaders/sample.wgsl` is the sole periodic bilinear sampling implementation for ocean drawing and lake composition. The module does not depend on SWE/lake/UI; optional `InputFilter` affects only the three matching nearshore water-level/momentum channels, with Shore adapting parameters at its own boundary. `offshore::Ocean`/`offshore::spectrum` retain compatibility with old calls while using the shared module internally. The lake holds clones of the same GPU handles rather than creating a second spectrum; window, snapshot, and MCP lake entry points each encode FFT once before composition. The lake uses only vertical wave height; its fixed shoreline does not participate in horizontal wave displacement.
- `simulation/nearshore/mod.rs::Shore` and its `shore*.wgsl`: local 2D SWE, first/second-order solving, surface foam transport, and beach wetting history. Coupling runs FFT → SWE; `uniform.rs` retains the original CPU → WGSL layout. Second-order water reuses a five-cell neighborhood, three reconstructions, and matching bed source terms per axis without adding passes or grid buffers. Model cell-center bed height directly indexes the uploaded grid, sharing the same query with collider editing; rendering at arbitrary world coordinates still interpolates. Normal advancement reads incident waves only in the FFT relaxation zone; reset still initializes the entire domain. CFL and RK2 stages are unchanged.
- In default single-concentration mode, nearshore foam quantity and momentum share conservative Rusanov flux; `foam_transport_order` defaults to 1 and can enable limited MUSCL spatial reconstruction with second-order SWE. Density and momentum share positivity/velocity constraints, locally falling back to first order at wet/dry boundaries, obstacles, and domain edges; source terms, drag, and material are unchanged. `foam-lab` independently selects spatial/temporal order and compares using the same CFL, recording GPU timestamps when supported.
- MUSCL foam reuses water depth, density, momentum, and terrain obstruction from a five-cell neighborhood per axis; the central slope is shared by both sides, without additional production grid buffers or compute passes. `Shore::solver_pipeline` lazily compiles and caches pipelines according to water/foam order using three shared bind group layouts, with WGSL overrides removing disabled solver branches; first use may incur compilation overhead. The diagnostic entry point can retain uniform-based dynamic selection.
- Nearshore source terms retain the old front/background paths. The experimental `foam_ridge_enabled`, off by default, reads five velocity samples along local flow in the same SWE stage, emits only into a narrow band of local compression peaks, and disables the background source. It is not FFT/J modulation and does not change hydrodynamics, transport, drag, decay, or material. `foam_emission_enabled` stops emission without clearing history; x/y of the third state block hold the actual source rate/weight of the latest substep in experimental or diagnostic views, while z/w retain surface elevation/velocity meaning. `simulation/nearshore/verification/foam_ridge.rs` verifies narrow bands, tangential connectivity, rectangular grids/rotation, wet/dry protection, both orders of injection, and conservative transport after emission stops through full GPU solver scheduling. There is no automatic wavefront tracking/hysteresis yet, and a net-like pattern is not guaranteed.
- `foam_dual_phase` is a dual-concentration experiment disabled by default and mutually exclusive with the default inertial/conservative path. The existing density slot stores fresh N + surface residue R, and w of the fifth block stores R; the five storage blocks remain the same size, and R does not belong to sand. When enabled, both share coarse SWE velocity and semi-Lagrangian backtracing, with area compression/expansion response applied to both and no additional old flux, drag, or single-concentration decay. Density transport and texture motion reuse the same backtraced position and actual transport velocity, but concentration obstacle-path checks and texture wet-contributor normalization remain independent. All existing sources directly inject only N; each full substep jointly integrates generation, N→R conversion, and independent decay analytically. Default half-lives are 1.4/9 simulation seconds, with an exit conversion fraction of 0.65. Switching modes resets SWE history; lifetime parameters update live, and pause, wet/dry, reset, and collider editing cover R. `simulation/nearshore/verification/foam_dual.rs` checks actual GPU analytical solutions, both solver orders, and transport/boundary behavior. This SL path does not promise strict mass conservation or overall frame-rate independence.
- `Shore::encode` splits substeps by stable timestep; second order has predictor and corrector stages. The dimensionless `ShoreConfig::cfl` limit defaults to 0.2, accepts finite values in 0.05–1.1, and is editable live in Shallow Water → SWE and Input → CFL Limit (C), without resetting history. It changes CPU substep scheduling only, not the Rust/WGSL uniform layout; integer rounding can give different limits the same actual step. Values above the default are experimental and do not retain the default water/foam stability and positivity assumptions. The predictor buffer still allocates five blocks, but normal prediction writes only the conserved-quantity and foam-momentum blocks (32 bytes per cell total, with momentum block zw zeroed); display/texture/wetting history needed by correction is read from the initial substep state. The full result still writes five blocks. Full substeps alternate output between field/previous, with prediction, correction, and initial-history bindings switching roles; one copy at frame end makes both complete fields consistent again. Rendering, pause, and collider editing still consume the fixed public field. `simulated_dt` is the actual amount advanced this time; long frames may be limited, so wall-clock time cannot directly replace it.
- `simulation/offshore/foam.rs` and its `foam.wgsl`: offshore foam and the current displacement Jacobian, independent of nearshore foam.
- `simulation/spray/mod.rs` and its `spray*.wgsl`: nearshore textured spray. Shore holds `SpraySource`, selecting bindings by current/initial field roles after each SWE substep and accumulating emission signals into a separate grid storage buffer. Renderer holds `SprayParticles`, consumes signals, and maintains GPU remainder, double particle lists, and indirect draw arguments. Particles do not affect water or foam; signals/particle counts are not read back at runtime. Configuration is in `OpticsConfig::spray`, disabled by default.
- `app/viewer.rs` implements the common `WindowScene`, handling ocean configuration application, business input, and frame scheduling. In normal ocean-mode frames it computes FFT, offshore foam, and SWE, then encodes particle updates, and finally draws the scene, spray, and GUI. `app/snapshot.rs` retains offscreen warmup and scheduling and also advances particles; the two paths have not been merged or reordered. `app/headless.rs` separately provides persistent single-instance offscreen mode `--headless`: it responds only to MCP stdio commands, advances in explicit 1/60-second steps, and reads screenshots of the current GPU scene. It does not read or write sessions by default; `--settings` permits explicit saving. It creates no window or GUI. `--no-ui` in `app/scene_window.rs` uses the same scene control and rendering schedule, shows only a scene window, and does not instantiate egui/Dock; the window advances by wall clock, and an independent MCP stdio thread forwards commands during the common loop phase.
- `render/caustics/` handles optional solar caustics on flat bottoms/sand slopes and static reef height fields: compute reads the shared FFT/SWE wave surface, analytically intersects planes, and queries a packed min/max quadtree hierarchy for models (rebuilt when terrain changes, with leaves conservatively covering bilinear neighborhoods and the nearest root found in candidate intervals). Beam area ratios accumulate additively into a 512×512 `Rgba16Float` world-space texture. `Renderer` encodes this before underwater predrawing and rebinds it when SWE is rebuilt. Sand replaces direct lighting; scanned models add focused brightening to underwater receivers matching the height field during water composition, retaining the unlit base color. `render/shaders/{scene_types,surface,water_light,caustic_sample}.wgsl` share types, wave surface, receiver geometry, and lighting sampling. View-ray refraction has an independent switch: flat bottoms/sand slopes use analytical intersections validated against screen depth; for models, `screen_depth.rs` builds a min/max depth mip every frame after opaque predrawing, and `screen_trace.wgsl` queries it hierarchically, updating background, optical path, and scattering direction on hits and falling back to a straight ray on failure. Both effects default off and do not write back to simulation. The caustics tab offers off and physical; the refraction tab offers off, fast, and physical. Old configurations retain their original enabled fields, with refraction method defaulting to physical. Fast refraction in `fast_refraction.wgsl` performs one local plane estimate, UV clamping, and depth-masked sampling without building hierarchical depth. Unselected physical passes are not encoded. See [Underwater caustics and refraction](guides/ocean.md#underwater-caustics-and-refraction) for parameters and single-layer height-field/screen-space boundaries; real-GPU checks belong to `render/verification/optics.rs` and `render/caustics/verification.rs` and can run separately with `--verify-optics`.
- `render/renderer.rs::Renderer` holds `Shore` and organizes sky, seabed, model, and water drawing. Both offshore and local SWE water use indexed meshes; `render/mesh.rs` generates UV vertices and indices for offshore, using a square grid by default or an optional staggered near-equilateral triangular grid with a similar triangle count. Even row counts and shared periodic boundaries ensure 3×3 tiling; WGSL reads the original FFT field from vertex UVs, with displacement and normal algorithms unchanged. When only offshore drawing topology/density changes, `app/viewer.rs` rebuilds only draw buffers, preserving FFT, SWE, foam, and spray history. Local indices remain square and rebuild with SWE resolution, unaffected by the offshore switch. CPU tests check count budgets, shape, winding, and periodic edges; `render/verification/mesh.rs` checks actual draw coverage and switching fallback via `--verify-optics`. Water writes `Depth32Float` depth; main depth has `RENDER_ATTACHMENT | TEXTURE_BINDING` usage, the scene pass saves depth, and the subsequent spray pass only samples it rather than also attaching it as writable.
- `render/post_process.rs` and `render/shaders/{post_process,agx}.wgsl` handle HDR/Bloom on the display path. Windows, snapshots, and offscreen profiling use `Renderer::new_display`, drawing the complete scene and spray to `Rgba16Float` before SDR output; `Renderer::new` retains raw linear output for physical verification. `OpticsConfig::post_process` defaults off and tolerates missing fields; its separate uniform does not change optics/SWE layouts. When the master switch is enabled, exposure comes first, with Bloom and AgX independently switchable. Bloom extracts highlights using linear RGB peak and a soft threshold, then composites through up to six independent down/up-sampling targets and normalized tent filtering. AgX uses Godot 4.6's generic Rec.709 matrices plus the allenwp analytical approximation, with fixed middle gray 0.18, contrast 1.25, and white point 16.29, without water- or material-specific grading. `agx.wgsl` retains provenance and the MIT license. Independent switches default to true but remain subject to the master switch, which defaults off; the uniform reuses unused components of the original 32-byte layout. Output is display-linear RGB, encoded only once by the final sRGB target. With the master switch off or in diagnostic views, only original color is output; disabling Bloom or setting its intensity to zero skips the bloom pyramid. GUI always follows post-processing. Resize rebuilds targets and bindings without resetting simulation; normal frames do not read back. `render/timing.rs` adds the `hdr_bloom_composite` GPU interval; `render/verification/post_process.rs` checks reference colors, grayscale monotonicity, middle gray, RGB/CMY extreme-highlight desaturation, -8/0/+8 stops of exposure, actual sRGB output encoding, independent switches, spread, bypass, and size boundaries via `--verify-optics`/full verification. See [HDR and Bloom post-processing](guides/ocean.md#hdr-and-bloom-post-processing) for parameters and ranges.
- Water SSR and model physical refraction share opaque scene color, a depth pyramid, and hierarchical traversal. The pyramid is built once whenever either effect needs it in the same frame. SSR calculates reflection direction using the same wave-surface normal and rejects underwater samples using wave height near the hit; screen edges and the distance limit fade to sky reflection. SSR defaults off.
- Shared water shading modules `render/water/shaders/{lighting,material}.wgsl` calculate direct solar highlights on water using a dielectric Cook–Torrance BRDF, including isotropic GGX, height-correlated Smith masking, and Schlick Fresnel calculated from refractive index. Sky and SSR are still sampled in the specular direction and composed with the water medium using view-angle Fresnel weights. The sky background draws the sun disk; water environment sampling retains only skylight and halo, with the sun disk's water contribution expressed by the BRDF. The shared refractive index applies independently of the viewing refraction mode.
- Nearshore wavelet normals in `render/shaders/surface.wgsl` use periodic Catmull–Rom bicubic reconstruction of the difference between 1-cell/4-cell central-difference slopes at FFT grid points, eliminating cross-cell derivative discontinuities in bilinear slopes; grid values, gain, wet/dry behavior, and footprint fading are unchanged. Water and foam reuse wavelet slopes while retaining their own base normals; caustic rays use the same reconstruction and their own sampling footprint. No field buffer or pass is added, and FFT main water geometry/vertex normals and SWE simulation are unchanged; `render/verification/surface.rs` checks actual GPU normals via `--verify-optics`/full verification.
- Nearshore material coordinates follow foam transport velocity. `foam_texture_distortion`, enabled by default, controls only whether rendering uses transported coordinates; when off, fixed world coordinates are used without stopping displacement history or concentration updates. The off flag is passed through `foam_velocity.w` without changing the uniform layout. The dual-phase reset period is controlled by `foam_texture_period` (default 2 simulation seconds, 0 for continuous transport); only the invisible coordinate layer is reset, without changing density/momentum. `foam_prototype` defaults off; when enabled it displays holes using three-scale value noise and a density threshold on transported coordinates, retaining existing optics, color, and density scale parameters without NSH micro-normals. Material debug 5 displays the transported-coordinate grid. This stage adds no fine-wave propagation, rock-impact source, or high-resolution foam field.
- The dual-concentration experiment's N appearance uses a segmented selector in `ui/panels/foam_material.rs` to switch constant/noise/texture, still defaulting to noise. The constant threshold defaults to 0.5; noise retains the original two-scale triangular-grid gradient noise, fine-layer rotation/offset, frequencies of 0.8/2.5 per meter, and fine-layer share of 0.3. Both modes retain the original density response and soft transition. Texture mode sends only N concentration to shared `nsh_material_phase`, reusing the bound three-layer NSH, coarse/fine sampling, micro-normals transformed by the transported-coordinate Jacobian, and roughness lighting. N texture source, size, micro-normal, roughness, and pore-coverage reference values are saved independently and do not overwrite the single-concentration material or debug color scale. R always retains multiscale narrow-band noise and original macro-normal lighting; each computes premultiplied color separately, then N is composited over R, with each coordinate phase shaded before blending. The shared opacity density scale remains in use for both exponential responses; texture mode changes only N's concentration-to-visible-coverage/lighting mapping, not concentration transport, generation, conversion, decay, or geometry. Six aligned vec4 uniforms for N appearance and N/R opacity match the shared WGSL definition and are material-only; substep upload/copy sizes are still calculated from the Rust struct size. Switching or editing does not reset history. All modes retain zero-concentration/thin-water protection and use the same water geometry, without fine-scale turbulence or individual bubbles. The rendered-component option can show all, N only, or R only, filtering appearance height accordingly and hiding offshore foam when viewing either alone; it is passed via ShoreUniform.density.w and has no effect when dual concentration is off. Density debug 6/9/10 reads N+R/N/R respectively without material thresholds; the dual-coordinate reset period remains effective. Real-GPU verification checks that all three N textures render pure N consistently with the original NSH, independent parameters take effect, R lighting/normal/opacity and density views remain isolated, and full state under both SWE orders is unaffected by N appearance. See [Ocean guide](guides/ocean.md) for parameters.
- The dual-concentration N/R `foam_*_density_opacity` switches default off; when enabled, each multiplies its own material coverage by `pow(clamp(own concentration / independent range,0,1),p)`, with range 0–10 and power 0.1–5, both defaulting to 1. Zero range uses the limiting step of 1 for positive concentration and 0 for zero concentration, without division by zero. Production `concentration_opacity` returns only the additional optical factor, scaling both the corresponding premultiplied color and opacity before N over R composition; it is available for all three N materials, and R parameters do not affect N. The UI conditionally displays parameters under their respective appearance groups, retains settings while disabled, and applies changes live without reset or changes to the solver or density debug. GPU numerical checks compare boundaries against an independent f64 power function; production raster checks verify independent factors and correct color/alpha blending for both components.
- Nearshore NSH foam in `render.wgsl` retains dual-phase pore coverage and uses the exponential response of original surface density to control continuous opacity. `ShoreConfig::foam_opacity_scale` controls appearance only, without changing density/momentum or resetting history. The original grayscale and offshore foam paths are independent.
- `parameters/` retains original parameter type names, fields, defaults, and validation. `OpticsConfig` remains the existing scene parameter aggregate without changing serialization structure. `render/{optics,skylight,seabed,model}.rs` and their shaders handle optics, seabed, sky, and model drawing; `scene/{terrain,collider,model}.rs` provide terrain, collision geometry, and imported model data.
- `render/textures/sand.rs` and its `color_mips.wgsl`: sand and imported model color textures are JPEG-decoded on CPU, and after uploading the original level, a GPU render pass generates the full sRGB mip chain in linear space without synchronously waiting for the GPU; each level is written back as 8-bit sRGB. Sand normal/scalar textures retain CPU filtering. `sand::verify` reads back actual GPU mips and checks linear-light averaging and rectangular texture boundaries.

## UI, configuration, and verification

- The header screenshot action in `ui/gui.rs` asks `app/viewer.rs` to copy the live Render View texture after scene rendering, without capturing the GUI or rerendering the simulation. `app/screenshot.rs` maps the staging buffer asynchronously and writes the PNG on a worker thread; ordinary frames do not copy viewport pixels.

- Common controls come from crates.io `yummy_egui` 0.1 series (minimum 0.1.2), alongside egui 0.34.3, egui_dock 0.19.1, and wgpu 29; library source and theme configuration are not stored in this repository. Ocean, both UI labs, and the standalone `tall-cell-fluid` demo use `Theme::default()`, and Dock uses its `dock_style()`, without reading or saving external themes. Titles consistently use h3; fonts are still installed by each host, with Ocean installing MiSans using `ui/fonts.rs`. The `tall-cell-fluid` UI dependencies remain enabled only under its `demo` feature, without changing its independent workspace and solver boundaries. See [yummy_egui](guides/yummy-egui.md) for integration conventions.

- `ui/gui.rs` uses egui_dock with a persistent toolbar and performance summary at the top, and fixed Scene, Shallow Water, Offshore, Animated SDF Ripples, Shading, and Configurations navigation on the left. The contiguous vertical segmented selector uses `yummy_egui::IconSegmentedControl::vertical()` and retains SVG icons and English tooltips; six independent layouts default to parameters on the left and Render View on the right, sharing simulation, drafts, and camera. `ui/workspace/` registers Ocean categories, panels, and version migration, delegating canonical layouts and temporary-hide restoration to common; each layout and the current category are saved independently to a `.workspaces.json` sidecar beside the writable session, with no implicit reads or writes in read-only/no-save mode. See the [workspace UI specification](specs/workspace-ui.md) for the UI contract. `ui/panels/lake.rs` provides separate Lake Terrain and Animated SDF Ripples panels, sharing a controller but applying terrain and propagation drafts independently; the latter uses a separate icon workspace without changing simulation or scene. `ui/panels/` splits panels by responsibility and shares `yummy_egui` parameter lists and controls. Action buttons explicitly use `PanelButton` to fill their cells: native egui button borders and interaction are retained, and text is centered in the content area using theme padding. Margin defaults in the embedded component theme to 4 pt above and below and 0 on the sides, is not clickable, and is not written to parameter or layout files. `action_row` arranges buttons at equal widths and stacks the entire group vertically if less than 96 pt remains per button after margin, without changing global button style. `ui/workspace/{mod,store}.rs` manages workspaces and the independent layout sidecar. `settings/{session,library,store}.rs` respectively manage the current parameter snapshot, named library, and loading/atomic manual saving. Only top-level Save/Ctrl+S or Save Configuration in the configuration panel triggers disk writes; editing, loading configurations, losing focus, and exiting do not write the session, and failures require manual retry.
