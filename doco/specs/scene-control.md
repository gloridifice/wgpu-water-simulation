# Single-scene MCP control (current implementation)

## Scope

- `ocean --headless` creates one persistent GPU Ocean instance without a window, Surface, egui, or Dock. By default, when neither `--config` nor `--settings` is supplied, it starts from the default configuration without reading the personal session; `--config PATH` is strictly read-only. `--settings PATH` explicitly opens a writable session, and only `configuration.save` writes to disk. `--headless` is mutually exclusive with snapshot, verification, and window frame-count modes.
- `ocean --no-ui` creates a scene-only window and MCP stdio, without egui, Dock, or layout state; `--frames N` permits a finite-frame preview. The window advances automatically by wall-clock time and `speed`, and stops when paused; external commands are processed in the event loop even when rendering is unavailable. `--headless` and `--no-ui` are mutually exclusive. Only MCP stdio is currently supported; each client starts a separate process and scene, and stdout carries JSON-RPC only. There is no HTTP or attachment to the ordinary parameter-panel window. common defines only commands and transport; Ocean exclusively owns the scene and executes commands sequentially.
- `tools/list` returns `scene_describe`, `parameters_get`, `parameters_patch`, `action_call`, `simulation_step`, and `frame_capture`. Execution errors return tool-level `isError`; successful results return `structuredContent`.

## Ocean configuration and actions

- `parameters_get` returns the applied `SavedSettings` and runtime scene, time, and version. The `changes` in `parameters_patch` map dot-separated paths to scalar values; array elements use numeric indices. Whole objects or arrays cannot be overwritten and fields cannot be added. Deserialization and full business validation precede submission; an invalid batch changes neither scene nor configuration. Resource rebuild failures return an error without committing the configuration; failure to prepare a scene using existing rendering resources triggers an attempt to restore the old scene.
- Writing `draft.*` only edits the offshore draft; `ocean.apply_draft` applies it to `ocean`. Writing `ocean.*` applies directly. Lake parameters `optics.lake.*` apply directly; terrain, propagation mode, or wave seed changes reset the wave field on the next advance. There is no separate lake draft. Changing only offshore mesh density or topology rebuilds only the draw mesh. Ocean and lake share `ocean` FFT parameters; lake `optics.lake.fft_strength` adjusts overlay strength live, with 0 disabling it. Emission and clearing affect only procedural shore waves, not the shared FFT. After a parameter patch, a zero-frame step can publish the wave field and diagnostic selection at the current time before capture.
- `action_call` supports applying the offshore draft, resetting simulation or camera, explicit lake emission or clearing, and explicit saving. Lake actions are available only in the lake scene; emission and clearing submit zero-step GPU commands within the action. Unimplemented UI buttons cannot be invoked by simulated clicks. `configuration.save` does not overwrite named snapshots or save Dock layouts; read-only mode rejects it.
- A headless instance does not automatically advance by wall clock; a `--no-ui` window does. `simulation_step` accepts 0–600 frames, each nonzero frame advancing the current instance by 1/60 simulated second. Initialization/reset zero steps do not consume requested frames; explicit steps are independent of `paused` and `speed`. The return value reports requested time and does not misrepresent the timestep actually accepted internally by SWE as elapsed time. A step returning means the command was submitted to the GPU queue, not that the GPU finished. `frame_capture` renders the current instance and blocks to read back a PNG (1280×800 in headless mode, current window size otherwise). The destination must not exist; no extra warmup or history replay occurs, and output has no UI.

The project's `.pi/mcp.json` starts an Ocean scene by default; the debugging skill is in `.agents/skills/ocean-scene-mcp/`.

## Limitations

Parameter discovery currently returns parameter root names and complete configuration values, not per-field units, ranges, or reset metadata; application validation remains authoritative. Operations run serially, so long steps block subsequent commands. HTTP concurrency control and scene switching outside the session are not provided. For detailed startup examples, see the [Ocean guide](../guides/ocean.md#headless-mcp-debugging).
