# 实现设计

## 1. Baseline and goals

基线为 `4b2b33d`，创建变更前工作区干净。本次只增加 doco 文档和本地工作流，不修改运行代码。需求和验收以 [proposal.md](../proposal.md) 为准。

已核查的接入点：

- `shore.rs::Shore::encode`：按 CFL 约束推进子步，记录 `simulated_dt`；二阶使用两个 stage，只在完成子步后把最终场复制到 `previous`。
- `shore_compute.wgsl::main`：近岸泡沫已有上升、流动追赶/碰撞等生成项；预测阶段提前返回。不能直接拿累积泡沫密度发射，也不能让现有泡沫生成参数隐式控制浪花。
- `viewer.rs`：常规帧中先 `Ocean::encode_filtered`、`Foam::encode`、`Shore::encode`，再渲染。快照路径有独立的模拟推进循环，也需接入。
- `gpu.rs::Renderer`：持有 Shore；水面写深度，但主深度没有采样用途且在 pass 结束时丢弃。软粒子需要调整用途和保存时机，不能假定已有深度可直接采样。
- `settings.rs::SavedSettings`、`optics.rs::OpticsConfig`、`gui.rs`：配置、合法值校验、持久化与面板入口。以上都没有浪花粒子 API。

## 2. Overall approach

拟新增 `spray.rs`、信号生成/粒子更新/绘制 WGSL，均限于 `ocean` feature。模块内分开两个资源所有者，不建立通用粒子引擎：

- `SpraySource` 由 Shore 持有，生成网格信号；只读 SWE 状态，独立 pass 写信号，不修改求解器输出。
- `SprayParticles` 由 Renderer 持有，消费信号并管理粒子、发射余量和间接参数。发射逻辑只依赖信号格式；落水检测另外读取当前水面/地面，不从泡沫状态反推发射事件。

```text
开始有效模拟帧：GPU 清零本帧发射信号
  SWE 完成一个子步（跳过预测阶段、重置初始化）
    → 独立 compute 读取子步前后水体状态，累积发射信号
    → 执行既有 previous 复制
  所有子步完成
    → 更新旧粒子并压紧存活列表
    → 消费信号、累积小数余量、追加新粒子
    → GPU 写间接绘制参数
  场景 pass：天空/海底/水面，保存深度
    → 粒子 pass：采样主深度、透明混合
    → GUI
```

清零、生产、消费和绘制在有序 GPU pass 中执行，不用 CPU 映射缓冲区来同步。GPU 粒子数量不参与 CPU dispatch 决策：固定容量 dispatch，在 shader 内检查 GPU 计数；绘制使用 indirect。

## 3. APIs and data model

以下均为计划接口，不是现有 API；命名可随实现调整，职责与数据边界不能合并：

| 计划入口 | 输入与职责 |
| --- | --- |
| `SpraySource::begin_frame(encoder)` | 有效模拟帧 GPU 清零信号；暂停保留最近信号用于调试，但消费时长为零，不能重复发射 |
| `SpraySource::encode_substep(encoder, inputs)` | inputs 含只读子步前后场、地形、域信息、独立浪花配置和子步时长；每完成一个子步调用一次 |
| `SpraySource::buffer()` | 返回 GPU buffer 引用及单元数，不返回 CPU 信号数组 |
| `SprayParticles::encode(encoder, source, surface, step)` | step 含实际推进秒数、重置标志、配置；surface 只供出生校正和碰撞；更新、发射、生成 indirect 参数 |
| `SprayParticles::render(encoder, target, depth, camera)` | 加载场景颜色，采样已保存深度，间接绘制纹理四边形 |

### 信号 ABI

每个 SWE 单元两个 16 字节向量，共 32 字节，Rust 与 WGSL 保持一致：

- `position_amount.xyz`：各子步世界坐标发射位置乘预期粒子数的累积和，单位米·粒子；`.w`：本帧已按时间与面积积分的预期粒子数，允许小数。
- `velocity_reserved.xyz`：初速度乘预期粒子数的累积和，单位米/秒·粒子；`.w` 保留为零。

消费时用累积权重求平均位置和初速度；零权重不做除法。首版按帧合并子步事件，不保留每次喷射的完整时间轨迹。这是视觉近似，不能声称逐粒子跨帧分割完全等价。消费端不得再次乘时间或单元面积。

生产端每次 dispatch 一个单元由一个 invocation 写入；子步串行，无需浮点原子。源位置包含水面高度，不能只记录网格坐标；近岸坐标及高度需与最终水面渲染变换一致。消费时按当前水面重新校正出生高度，若位置已干燥则丢弃，不延迟补发。

### 粒子、计数与余量

- 两个固定容量粒子 buffer 交替作为上一帧和下一帧。粒子包含世界位置/年龄、速度/寿命、尺寸/旋转/纹理索引等视觉数据；不持久化到配置文件。
- 每个列表有 GPU 活跃计数；独立 indirect buffer 使用 `STORAGE | INDIRECT`。下一帧列表先清计数，再写存活粒子，最后追加新生粒子。
- 每发射单元保存小数余量和出生序号。余量属于粒子消费端，不随每帧信号清零；出生序号用于固定种子的随机扰动，不用现实时间或 CPU 帧率作随机源。
- 消费信号只需只读 storage 绑定。所有运行时粒子资源不需要 `MAP_READ`；验证用复制/读回只存在于独立验证入口。
- 网格大小、域位置或谱重建导致采样映射改变时，重建绑定并清空信号、余量、粒子和 indirect 参数。窗口缩放只重建深度相关资源，不重置物理状态。

### 配置与资源失败

拟在 `OpticsConfig` 下增加独立 `SprayConfig`，使用默认值反序列化；默认关闭。参数覆盖发射密度（粒子/平方米/模拟秒）、坡度与上升门控、水深门控（米）、速度（米/秒）、寿命（模拟秒）、尺寸（米）、阻力（每秒）、软交界距离（米）、开关与发射调试视图。默认视觉数值、范围和内部容量需在实现时一并选择、校验、注明，而非沿用泡沫阈值或单位。

配置里的数值必须有限并在合法范围；不序列化运行中粒子。容量先作为有界内部预算，不增加任意可写的超大分配参数。按设备 buffer/binding 限制验证内存需求；无法分配时禁用浪花并给出明确错误，海洋原有模式仍可使用，不能退化成 CPU 粒子路径。

## 4. Algorithms and rules

### 发射判据

使用独立、可调的视觉近似：有效水深门控 × 水面坡度门控 × 正向水面上升门控 × 近岸有效域权重。坡度从水面高程取梯度，不从水深取梯度。上升速度使用已完成子步前后的水面变化除以子步时长；零时长不发射。计算只读取一致的完成状态，不能把中心的新值和邻居的旧值混用。

发射密度乘单元世界面积、子步实际时长及上述权重，得到预期粒子数。平静水面、干地、平坦匀速退水为零；流速不单独触发发射。已有破碎/汇聚算法可作为实现参考，但首版不直接复制既有泡沫源项，也不把汇聚额外乘到泡沫输送上。

初速度采用水体水平速度，加沿水平方向的喷射和向上喷射；静止或方向不可靠时水平附加速度为零。随机锥形扰动由消费端添加。水滴在静止空气中受线性阻力与重力，首版不增加独立风场。

### 容量与时间

1. 更新上一列表的活跃粒子，按实际 `Shore::simulated_dt` 推进。寿命耗尽、非有限状态、落水/触地或离开有效近岸域时剔除；用有界模拟子步和跨水面检测避免快速粒子穿透。
2. 将存活粒子原子追加至下一列表。其数量不超过原容量，因此不会因新生粒子抢占而被覆盖。
3. 每单元把积分量加到余量，取整数发射请求，保留 `[0,1)` 的小数部分。使用有界原子槽位预留，容量满时立即放弃未满足的整数请求；不以无界循环等待空闲，也不保留整数积欠。
4. 单独 compute pass 在所有追加结束后写入 6 顶点四边形的间接绘制参数，实例数不超过容量。
5. 暂停时冻结粒子运动和年龄，不再次消费信号；显示可以继续绘制。禁用时清空一次后跳过源生成、粒子计算和绘制；重置时同时清零余量、计数和出生序号。

CPU 可以交换双缓冲引用和提交已知数量的 dispatch；不能读取活跃数、生成发射列表或根据回读决定重试。大帧停顿使用实际推进量，不补算被 SWE 丢弃的墙钟时间。

### 纹理渲染

首版使用一张随仓库发布、来源和许可明确的碎浪透明纹理或小图集。采用面向相机的四边形，可限制性地沿速度拉伸；预乘透明度混合，生命周期淡入淡出，简单环境光/太阳光响应，不使用纯加法发光。

主深度增加 `TEXTURE_BINDING`，场景 pass 改为保存深度。粒子使用独立 pass，不把同一深度纹理同时作为可写附件和采样输入：首版选择只采样深度，在 fragment 中执行遮挡判断与线性深度差淡出，粒子 pass 不挂主深度附件。使用同一相机的深度转换并覆盖窗口 resize。当前水面确实写入主深度，因此可参与软交界。

首版不排序、不做 OIT，接受稀疏同类透明粒子的重叠近似；不得为掩盖次序问题切换为纯加法。纹理尺寸与覆盖量需有界，暂不加入低分辨率粒子渲染。调试视图读取 GPU 信号显示按面积/时间归一的发射强度，不通过 CPU 下载网格。

## 5. Fixed decisions and discretion

- 用户明确约束：简单纹理粒子；GPU 缓冲区传递发射信号，GPU 消费，无运行时 CPU 回读依赖。
- 本设计选择：先做近岸、固定网格信号、完成子步后独立生产 pass、GPU 双缓冲压紧粒子池、单向耦合、预乘透明度、采样主深度软化。它们是本变更的拟实施方案，不记录为用户已逐项批准的事实。
- 实现自由度：文件细分、函数命名、workgroup 大小、有界容量预算、纹理图块、美术参数的初值与合法范围。最终选择须写入代码和使用说明，并以实际 GPU 验证，不声称未经测量的性能。
- 实施细化：容量采用 65,536，信号/粒子 workgroup 为 64；仅在 FFT 权重约不大于 0.001 的纯 SWE 区域出生，避免近岸/FFT 混合几何的逆映射。按后续用户要求改用 Effekseer 官方 Pierre 样例的 CC0 Splash 图集：四种随机 Alpha 图层，独立透明边及完整 mip 链；原图与许可记录随仓库保存。默认参数与合法范围已写入 README。暂停保留源强调试画面，消费者步长仍为零；碰撞体编辑清空旧粒子和信号。发射信号全部计入 SWE GPU 时间戳范围，粒子更新与绘制不计入。以上不扩展远海、反作用或三维碰撞范围。
- 无阻塞性算法问题；若实施时发现必须依赖 CPU 信号回读、修改水体求解或新增远海发射才能达成效果，应先修订方案，不隐式扩大范围。

## 6. Verification and documentation impact

验证行为而非源码字符串或调用次数。既有 SWE/泡沫验证继续负责原数值行为；新增验证集中在真实 GPU 信号→粒子链路和配置兼容边界，不复制一套模拟算法作为期望值。

- 已知常量源：不同时间分割/网格面积下累计出生量、余量、容量饱和后恢复；只在专用验证末尾读回。
- 规定静水、干地、平坦回流、上升陡坡：检查源强的零/非零与有限性；一阶/二阶都检查不重复积算。
- GPU 生命周期：暂停、重置、禁用/再启用、重建后的旧信号和粒子不能泄漏；开关浪花前后水体和泡沫状态保持不变。
- 配置缺字段、往返保存、非有限/越界输入由配置层测试负责；不为纯面板布局增加复述实现的测试。
- 固定条件的有界预览与窗口截图检查软交界、遮挡和 resize。`--snapshot` 只验证画面，不作为面板布局证据；预览使用 `--no-settings`。
